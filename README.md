# Finleet MVP

#### **Notice: the description is full of AI slope. The only thing that you need to know is how to build and how to run. The Run section should have enough live examples for you to start.**


**CURRENT:** Finleet is an npm workspace with exactly two packages. `packages/finleet-core` owns the durable domain/runtime, providers, tools, `CoreService`, authenticated loopback JSON-RPC/WebSocket server, protocol, and headless CLI. `packages/finleet-tui` owns terminal presentation, image/LaTeX/chart rendering, browser helpers, and the native safe-mutate helper. The TUI launches core as a child process, reads one bounded `{url,token}` handshake line, and then communicates only through the authenticated no-compression loopback WebSocket boundary.

**NORMATIVE:** `docs/implementation-guild.md` governs `INV-ADMISSION-DURABLE`, `INV-EXECUTION-SERIAL`, `INV-TURN-ONE-STREAM`, `INV-HISTORY-PROJECTED`, typed/authorized tools, recorded-outcome replay, and immutable plans.

**PROPOSED:** The local graph snapshot is a full append-only plan record with a digest calculated internally. Improvement proposals are immutable non-active data records only; no proposal can activate a plan.

**CURRENT:** The local fake-provider primary tool registry exposes a bounded background-agent MVP: `spawn_agent` starts an independent, durable child session using only the named `read-only-research` profile, and `get_agent`, `wait_agent`, `read_agent_output`, and `cancel_agent` provide parent-owned control. Children use the canonical Runner and provider path with paper-market read access only, one-turn/30-second bounds, depth one, bounded redacted fresh or admission-time parent snapshots, durable lifecycle/output records, and core-service-brokered approvals. Provider-owned execution remains deferred rather than creating an alternate local execution path. This is not a worker gateway or general multi-agent platform.

### Background-agent delivery

`spawn_agent` without `mode` preserves the legacy immediate response containing agent metadata. With `mode: "blocking"`, it waits for the bounded terminal result and returns an untrusted terminal envelope: completed work includes bounded, redacted output, while failed, cancelled, and recovery-required work includes a bounded, redacted `{ code, message }` error. With `mode: "async"`, it returns immediately with stable agent metadata, a `callbackId`, and a deterministic `batchId`. Async siblings created in one parent provider turn are durably sealed only after that turn has a terminal record. Each child retains its own bounded/redacted terminal callback as source data; once every sealed member is terminal, Finleet materializes exactly one ordered `background_agent_batch_callback` after the last originating spawn result. Its host-owned payload requires one synthesis across all members, comparison of evidence, reporting conflicts and failed/cancelled/recovery members, and treating every member result as untrusted data rather than instructions. The host consumes that aggregate through its normal serialized session/lease path and writes one batch delivery acknowledgment only after the provider completes a synthesis turn. Recorded provider failures remain undelivered and retry with a fresh durable effect; an ambiguous claimed effect fails closed for reconciliation rather than risking duplicate synthesis. Restarts reconcile interrupted children to recovery-required first, then retry ready undelivered batches; legacy unbatched journals retain per-child `background_agent_callback` delivery.

**DEFERRED:** exchange APIs and trading, keychain/secrets-manager integration, worker gateway, app, sandbox, brokers/OMS credentials, remote MCP/OAuth, executable plugins, unrestricted multi-agent execution, live replay, and autonomous plan activation. `models.dev`-compatible metadata is advisory only; `models sync --remote` is an explicit HTTPS cache refresh, never a runtime availability guarantee. Native exchange API, local exchange CLI, and local stdio MCP connectors are typed deferred records only and cannot execute tools or trades.

**CURRENT:** Finleet implements Codex-inspired durable session semantics, not full Codex parity. A session is created by its first durable prompt admission; `sessions list` returns bounded metadata sorted by newest durable activity, while `session show` loads the projected transcript on demand without invoking a provider or tool. `exec` admits then executes through the canonical EventLog and Runner. `exec resume <id>` / `resume <id>` and `--last` append a newly admitted prompt to an existing durable session; `--last` resolves deterministically by newest activity. Scripted `exec -` accepts bounded non-empty stdin (512 bytes maximum). `agent run` remains the explicit compatibility alias.

**NORMATIVE:** The session CLI preserves `INV-ADMISSION-DURABLE`, `INV-EXECUTION-SERIAL`, `INV-TURN-ONE-STREAM`, and `INV-HISTORY-PROJECTED`; it must not create an alternate in-memory loop or bypass provider, tool, lease, permission, or replay boundaries.

**PROPOSED:** None for the JSON session interface.

**CURRENT:** The OpenCode-inspired terminal UI is available through the `finleet` executable (`packages/finleet-tui`). It starts `finleet-core serve` as its owned child, accepts only its bounded loopback endpoint/token handshake, then uses authenticated no-compression JSON-RPC for every request. Core remains usable headlessly via `finleet-core`; tokens, credential files, journal paths, and approval authority are never RPC payloads. The UI provides a persistent coding/chat transcript, slash commands, model selection, agent/thinking/detail toggles, selectable collapsible harness rows, inline harness details, terminal image previews, and safe terminal Markdown rendering.

### Agent instructions

Every provider job receives two ordered instruction layers. The first is the agent-selection policy from `~/.config/finleet/AGENT_SELECTOR.md`; when that file is missing, Finleet uses its built-in policy, which selects the current `default` profile. Set `FINLEET_AGENT_SELECTOR_FILE` to use another selector file. The second is the selected-agent prompt: Finleet starts with its built-in default-agent prompt, appends `~/.config/finleet/AGENT.md`, and then appends `AGENT.md` from the selected working folder. Set `FINLEET_AGENT_FILE` to use a different global agent file. This layering applies to primary, continuation, callback, and background-agent provider turns. It does not make a separate model call for selection; the selector is the first system-context layer so durable execution retains one provider stream per turn.

Missing customization files are ignored. Each file is bounded to 16 KiB and credential-shaped values are redacted before instructions are sent to a provider. Use `workingDirectory` when embedding the CLI, or run Finleet from the desired working folder. Instructions are provider context only and are not written to the journal or projected history. A minimal customization is:

```text
~/.config/finleet/AGENT_SELECTOR.md  # first layer: selection policy
~/.config/finleet/AGENT.md           # second layer: default selected agent
<workspace>/AGENT.md                 # project-specific selected-agent additions
```

Build first, then launch it from an interactive terminal:

```sh
npm run build
node packages/finleet-tui/dist/cli.js --provider openai-responses --model gpt-5.6-luna --journal ./tmp/finleet-tui.jsonl
```

Use `/help` inside the TUI. `/model <provider/model>` changes the selected model, `/agent` toggles the visible agent mode, `/thinking` toggles thinking visibility, `/details` expands harness events, `/harness <n>` toggles a numbered harness row and its inline detail, `/scroll up|down|top|bottom` scrolls accumulated harness history, `/image <path>` renders a local image, and `/quit` exits. Successful image previews are retained in the transient rendering area and replayed after later screen redraws; they are not written to durable history. Typing temporarily yields the preview rows to the input bar. Submitting a prompt archives and hides the old preview before thinking and model output begin; scrolling up or to the top reveals it again, while returning to the latest history hides it. When the input bar is empty, Up/Down navigates eligible non-slash prompts already admitted in the current session; non-empty input keeps normal readline editing behavior. When a local tool needs a declared capability, the TUI pauses execution and shows a confirmation card with the tool, redacted arguments, and review steps. Choose `[1] Allow once`, `[2] Allow during this session`, `[A] Allow this job`, or `[3] Reject`; arrows, `h`/`j`/`k`/`l`, and mouse buttons are supported. Type `s <feedback>` then Enter to reject with a bounded suggestion for the next step. Session grants live only in memory and are never persisted as approvals. Panels clamp to a safe terminal width and wrap visible content, retaining a grey background and colored left rail. When the terminal supports SGR mouse reporting, left-click-drag over rendered history text and release copies the cell-aware selection to the system clipboard; a click without dragging keeps the existing link-opening and harness-toggle behavior. Wheel buttons 64/65 scroll history, and keyboard commands remain available as a fallback. Clipboard writes use `pbcopy` on macOS, `clip.exe` on Windows, and `wl-copy`, `xclip`, or `xsel` on Linux without a shell. Detail data is terminal-sanitized and uses the journal’s redaction rules, so credentials are not displayed. The existing Runner remains authoritative for admission, durable history, leases, effects, permissions, and replay.

`/image` detects terminal graphics support and selects Kitty Graphics, iTerm2 inline images, SIXEL, or ANSI fallback in that order. Kitty receives a normalized PNG encoding, while iTerm2 receives the original supported image bytes; SIXEL decodes and bounds the image before palette-based encoding. iTerm2 previews reserve guard rows around the inline image block so adjacent TUI text cannot overlap it. A leading `~/` path is expanded against the current user's home directory, and image files are limited to 16 MiB with a 16-million-pixel decoded limit.

Permission capabilities are explicit and non-transitive: `market:read`, `web:read`, and `shell:read` cover read-only operations; `market:write`, `web:write`, and `shell:write` are separate approval capabilities for market-changing operations, HTTP mutations such as POST/DELETE, and shell mutations respectively. `account:read` remains available for account context. Write capabilities are not granted by default; a write-capable tool must resolve the matching write permission for its concrete request and go through the same confirmation card.

Permission decisions include allow once, allow job, allow session, and reject. Allow-job applies only to the current durable prompt admission, including continuation windows, and is removed when that job ends; it never applies to later prompts or independent background-child jobs. Allow-session remains an in-memory capability-and-scope grant for the current approval owner. Neither decision is persisted or a global bypass.

### Direct OpenAI Responses development path

`finleet auth login --provider openai --format json` runs the PicoClaw-compatible OpenAI OAuth flow: PKCE, CSRF state, a localhost callback on port 1455, authorization-code exchange, and secure credential persistence. `FINLEET_OPENAI_CLIENT_ID` may provide a runtime client-ID override. The flow never prints or persists access/refresh tokens in CLI output or durable session events.

The only live invocation is the exact fixed command shown above: provider `openai-responses`, model `gpt-5.6-luna`, reasoning effort `high`, paper exchange, and JSON output. With `OPENAI_API_KEY`, it sends one request to the official `https://api.openai.com/v1/responses` endpoint. With OAuth credentials from `auth login`, it uses PicoClaw's Codex-compatible `https://chatgpt.com/backend-api/codex/responses` route with the OAuth access token, `Chatgpt-Account-Id`, `originator: codex_cli_rs`, and `OpenAI-Beta: responses=experimental`; pass `--auth-file PATH` to execution when using a non-default credential file. No key or token is written to a journal, history, replay, request body, or error output; OAuth credentials are intentionally stored in the plaintext auth file described below. This direct development path is not the future gateway or multi-tenant architecture.

**CURRENT:** Finleet can safely inspect a Finleet-owned plaintext OAuth credential file with `finleet auth status --format json [--auth-file PATH]`. The default file is `${HOME}/.local/share/finleet/auth.json` on macOS/Linux and `${USERPROFILE}\\.local\\share\\finleet\\auth.json` on Windows. On Unix, the directory is mode `0700` and the atomically replaced file is mode `0600`; `FINLEET_AUTH_CONTENT`, when valid JSON, is read in preference to the file and is never persisted. Status emits provider metadata and source only, never access or refresh tokens.

**NORMATIVE:** This is plaintext-at-rest storage, not a secrets manager. It remains accessible to the same user, root, backups, and any container or process with access to that user’s filesystem. `auth login` and OAuth refresh intentionally write credentials to this file; credentials are not sent to EventLog, Runner, replay projections, CLI errors, or request bodies.

The resolver gives `OPENAI_API_KEY` precedence. Otherwise it loads the `openai` OAuth credential from `FINLEET_AUTH_CONTENT`, `--auth-file`, or the default auth file, refreshes credentials within five minutes of expiry, and persists rotated file credentials atomically. OAuth execution requires an account ID; missing or invalid credentials fail before admission. Token refresh preserves the prior refresh token and account metadata when the provider omits them, while environment-injected credentials remain non-persistent.

`--delivery queue` is FIFO at idle; `--delivery steer` is promoted before waiting queue entries at the next safe one-turn boundary. Exact prompt-ID retries are idempotent only when the session, delivery, and canonicalized/redacted durable prompt match; a completed matching retry returns its recorded outcome without starting another provider stream. Replay reads recorded outcomes and projected history only—it never invokes providers or tools.

The default harness includes a `fetch_page` tool backed by the official Obscura CLI. `npm run obscura:install` downloads the pinned, SHA-256-verified release archive into `.tools/obscura`; the tool automatically prefers that project-local binary. The installer supports macOS and Linux; on other platforms install Obscura separately and set `FINLEET_OBSCURA_BIN`. Fetch requests accept `format: markdown` (default), `format: html` for the post-JavaScript rendered DOM, or `format: original` for the raw server response; `format: url` is invalid. HTML requests wait for the page load event, while Markdown and original output use `domcontentloaded` without an unconditional delay. All output remains bounded to 8192 characters before tool encoding and 512 characters in durable/provider-visible tool results, so this is not an unlimited HTML dump. The command is equivalent to `obscura fetch <URL> --dump <format> --timeout 30`; Finleet explicitly passes Obscura's `--allow-private-network` by default to match its internal setting, while programmatic `allowPrivateNetwork: false` omits that flag and rejects private targets before execution. All requests require credential-free HTTPS URLs, bounds returned content before durable recording, and require `web:read`. Advertised Finleet tools are explicitly local-owned: when a supporting provider returns one, Runner claims and records the typed tool effect, stores only a bounded redacted result, projects that result with its original call ID, and makes one bounded continuation request. Provider-owned calls remain deferred and are never dispatched by Finleet locally. Fetch process failures retain only bounded, redacted exit diagnostics in the durable tool event. The harness also provides arbitrary host bash only through its dynamic, interactive `shell:write` approval flow; it is deliberately non-sandboxed.
Obscura runs with stealth mode and private-network access enabled by default. Markdown and original fetches wait for `domcontentloaded` without an unconditional post-load delay, keeping simple fetches responsive; HTML fetches wait for `load` plus five seconds so client-rendered DOM content has time to appear. This is intentional for harness environments; the tool still requires HTTPS, rejects URL credentials and fragments, and rejects credential-like query parameters while allowing ordinary page parameters such as `?hl=en`. TUI link opening is intentionally stricter than Obscura fetching and rejects every query string and fragment. These are internal tool settings and are not exposed as CLI options.

The `bash` tool resolves a dynamic `shell:write` requirement for every command rather than advertising a static capability. It accepts arbitrary bash scripts, including arbitrary host paths, shell operators, and installed binaries; this is deliberate host authority, **not a sandbox** or workspace confinement. Every invocation requires interactive approval for an identity-bound scope that explicitly identifies `host:arbitrary-bash` and the canonical working folder device/inode. **Allow during this session** is cached only for that exact permission and scope. Non-interactive calls fail closed with `TOOL_PERMISSION_REQUIRED`, and an approval is a Runner-issued opaque capability that cannot be supplied by a request object. Commands execute from the selected working folder using `/bin/bash --noprofile --norc -c`, a fixed minimal environment and PATH without inherited application credentials, a 10-second timeout, bounded redacted output, and process-group termination on abort/timeout. These operational bounds limit accidental exposure and resource use; they do not isolate the host.

Provider text is bounded to 512 characters; tool previews are bounded to 256. Immutable plans permit eight provider turns per execution window. When a local tool continuation is required, Runner records the provider and local tool effects, appends `ContinuationWindowOpened`, and starts a deterministic child graph run for the same admitted input without another `InputPromoted`; the child reloads projected journal history. Durable same-session continuation has no configured total-window or total-turn cap, while each provider window, provider stream, local tool, context payload, and durable identifier retains its own safety bound. Tool effect identity is admission-stable; provider effect identity is child-run scoped. Durable payloads redact both secret-like keys (`apiKey`, `api_key`, `api-key`, `accessToken`, `access_token`, `clientSecret`, `client_secret`, `authorization`, `token`, `password`, `secret`) and credential-like text before being written to the journal. Cancellation, provider/tool failures, timeout, recovery-required states, and representational overflow still stop execution fail-closed. Finance context requires explicit permissions: the default paper runner receives market context only, never account data.

Each admission atomically reserves its prompt ID with a journal-side owner lock before it reads, checks, and appends; live or unverifiable owners return `ADMISSION_BUSY`, while only a verified dead owner can be recovered. Each runner obtains an exclusive atomic session lock before selecting or promoting inbox input. A provider turn is claimed and recorded before invocation; local tool effects follow the same claim/record/replay boundary. After a crash, an untouched, fully recorded continuation handoff resumes its deterministic child window; claimed or otherwise unrecorded effects still fail closed with `SESSION_RECOVERY_REQUIRED`, and Finleet never re-runs an ambiguous effect. Pass `--allow-all-permissions` only in a trusted, disposable environment; it automatically allows every interactive permission request and prevents permission cards from appearing.

### Catalog-compatible providers

`providers list` queries `https://models.dev/api.json` directly and prints a human-readable summary by default. Use `--format json` for scripts or `--format text` for readable output. If `--cache PATH` is supplied, that local cache is used only when the online request is unavailable; `--offline` is not supported for provider listing. All models.dev records remain discoverable through `models list`; `models sync --remote --url https://models.dev/api.json` accepts the real direct provider map (`{providerId: {id, npm, api, env, models}}`). It normalizes boolean capabilities, input/output modalities, and a model's positive `limit.context`, but discovery never grants execution permission.

Commands accept `--format text` or `--format json`; text is the default when the option is omitted. JSON remains the compact, script-friendly representation, while text uses readable formatting for terminal use. Execution commands retain their durable, paper-only behavior regardless of output format.

A provider becomes executable only when the same models.dev provider record supplies all of: an exact supported official package name, an explicit HTTPS `api`, and exactly one non-empty declared credential environment variable. Finleet derives only these trusted mappings:

```json
{"npm":"@ai-sdk/openai-compatible","api":"https://provider.example/v1","env":["PROVIDER_API_KEY"]}
{"npm":"@ai-sdk/anthropic","api":"https://anthropic-compatible.example","env":["ANTHROPIC_API_KEY"]}
```

These derive `ai-sdk/openai-compatible` with `openai-chat-completions` and `ai-sdk/anthropic` with `anthropic-messages`, respectively. The request is executed through the matching official AI SDK adapter; Anthropic uses the SDK's native Messages SSE stream. Finleet never guesses endpoints, appends routes, or treats other native providers as executable. For example, a discoverable Anthropic record with `api: null` remains `PROVIDER_NATIVE_UNSUPPORTED`.

`--model` must be the selected `provider/model`, the configured environment variable must be non-empty, and the model needs a positive context limit. Under the EventLog admission lock, Finleet conservatively compares projected history, prompt characters, and a 400-character system budget to `limit.context`; overflow is rejected without writing a durable event. Exact admission retries return their recorded admission before this validation. Missing catalog, execution metadata, credential, context limit, malformed catalog, and unavailable model return typed errors. Credentials are only passed as authorization headers and never written to catalog files, request payloads, journals, CLI output, or errors. Only explicitly local-owned calls for advertised Finleet tools enter the typed, authorized `ToolRegistry`; all provider-owned calls remain deferred.
### Bash inspection tool

The harness advertises a `bash` tool for arbitrary host bash scripts, with no static permission because Runner resolves an interactive `shell:write` requirement for every invocation. It accepts a structured `{ "command": "..." }` call up to 4096 characters, permits shell syntax, arbitrary installed binaries, and arbitrary host paths, and starts from the selected working folder. It is intentionally not workspace-confined and does not claim sandbox isolation: approval grants host authority. The approval scope explicitly says `host:arbitrary-bash` and includes the canonical working-folder device/inode identity, so session approval remains limited to that exact authority context. Approval is opaque and Runner-issued; direct tool execution, request objects, or a forged lookalike cannot bypass it. Bash is executed only as `/bin/bash --noprofile --norc -c <command>` (or `bash.exe` on Windows), without shell interpolation around the script argument. The child receives a fixed PATH and minimal non-secret environment rather than inherited application credentials, output is redacted and bounded, and a 10-second timeout or abort terminates the process group where supported. Tool calls and approval rejections remain durably recorded by the existing Runner. These bounds are operational safeguards, not OS isolation.
